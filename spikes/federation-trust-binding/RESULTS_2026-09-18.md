## 実証した境界

- Identity検証ではexpected Trust Domainに対応するBundleだけを使う
- Company C IdentityをCompany B namespaceとして扱わない
- Federation AdministratorのTrust Rootをcallerから差し替えられない
- Bundle Versionのrollback / replayを拒否する
- rotation overlapでold / new両Keyを扱える
- old key削除後はold Identityを再検証しない
- 同一Keyが複数Trust Domainに存在してもIdentity namespaceを統合しない
- 未Federation Domainを他Domainとの関係から自動Trustしない
- expired Identityを拒否する

## 解釈上の注意

このSpikeではEd25519と単純なversion番号を使っています。

SPIFFE / SPIRE、Bundle Endpoint、OIDC、X.509等の採否を決めていません。

確認できたのは、

> Identity namespace、Trust Material、更新Authority、freshnessを別の情報として保持し、そのbindingを検証できる

という点です。

## 次に残るもの

- Endpoint URL / profileの安全なbootstrap
- Admin key rotation
- emergency revocation
- federation config audit
- peerごとのAuthorization
- 実際のSPIFFE Bundle / sequence numberとのAdapter可能性
