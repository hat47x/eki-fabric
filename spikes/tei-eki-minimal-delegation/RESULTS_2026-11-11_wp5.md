## 観測

### WP-5: D3・D4を満たした

```
=== RUN   TestTEIValidationResultIsAcceptedAndReadable
    D3: AcceptedResult recorded d1d220ad… for attempt atm_dbe5181e…
    D4: GET result = 200, output_digest = d1d220ad…, body re-hashes to its name
--- PASS
```

| 完了条件 | 結果 | 根拠 |
|---|---|---|
| D3 EKIの受理 | 満たす | `resultacceptance.Accept`が2件の独立検証でAcceptedResultを記録した |
| D4 Receipt | 満たす | `GET /v1/tasks/{id}/result`が200、`output_digest`はTEIのローカル期待値と一致。取得した本文を再測定しても名前と一致 |
| Taskの終端 | 満たす | `terminal` / `completed` |
| 実行の成功 | 満たす | ラッパーのreportが`exit=0` |

**この受理は試験が注入したものです。** 実配備では、`claimaccept`が`resultacceptance`を呼びますが、既定ポリシー（RA2・threshold 2・principal/operatorの2次元）に対し、`defaultProducers`がどちらもWorker identityを返すため、Claim 1件ではquorumに届きません。試験は独立した2件のVerificationを`Accept`へ渡しています。**独立した検証者が実在することの証明ではありません。** 本番の受理をT1の受入に含める場合は、EKI #242のOwner判断が必要です（DR-3）。

### WP-10: Lease失効でAttemptが閉じ、古いAssignmentは配られない。ただしTaskは回復しない

```
=== RUN   TestTEILeaseExpiryClosesTheAttempt
    the Task was dispatched to wrk_49afcb5a…: attempt=atm_dbd74064…
    after the close: status=running terminal_code="" attempt_count=1
    the Task is in phase "active" after its Attempt was closed for an expired Lease
    attempts after the close: 1
    NOT RECOVERED: no second Attempt was created after the Lease expired (#745 recovery gap)
--- PASS (71.98s)
```

| 観測項目 | 結果 |
|---|---|
| Leaseが失効したAttemptの閉鎖 | 閉じた。`close_reason`は`lease_expired` |
| Claimの不在 | Claimは無い（実行したWorkerがいない） |
| Lease registryからの除去 | 除去された |
| 古いAssignmentの再配送 | 配られない（期限切れのLeaseはlistingから落ちる。閉鎖後に起動したAgentは、そのAttemptのイベントを一つも受けなかった） |
| Taskの回復 | **しない。** Taskは`active`のまま、Attemptは1件のまま |
| 公開status | `running`、`terminal_code`なし、`attempt_count`は1 |

**回復しないことを失敗とも成功とも記録しません。** 観測された事実として、このrevisionではLease失効の後に新しいAttemptが作られないことを記録します。TEIのReceiptはこの状態を`undetermined`と読みます（結果が来ないまま期限を過ぎる）。

試験時間は72秒でした。`RecallGrace` 30秒と回収間隔1分固定のためです。間隔を設定可能にする変更は、起動経路の変更なのでEKIのレビューで決めます。

### WP-11: 本文が退役した結果は`accepted`にならない

```
=== RUN   TestTEIResultWhoseBodyWasRetiredIsNotAccepted
    after retirement: outcome=undetermined available=0 fetched=0
--- PASS
```

| 観測項目 | 結果 |
|---|---|
| 退役前 | `available: true`、`artifact_id`あり、取得して再測定で一致 |
| 退役後（メタの期限を過去にし、本文を削除） | `available: false`、`artifact_id`なし、`size_bytes`と`sha256`は残る |
| 退役後の取得 | 410または404 |
| TEIのReceipt | `undetermined`（`available 0`、`fetched 0`）。`accepted`ではない |

TEIは`undetermined`にしました。これは「結果が無い」ではなく「結果はあるが本文を確かめられない」であり、`rejected`とも区別しています。

## 一般化できる範囲

- **結果の受理と取得は、実EKIの公開APIで通しで動く。** 試験が検証を注入する限り、AcceptedResultが記録され、結果は200で返り、本文は名前に一致する。
- **Lease失効は、Attemptを閉じるが、Taskを回復させない。** このrevisionの観測事実であり、回復を期待する利用者にとっては制約になる。
- **本文が退役した結果は、`available: false`として記録が残る。** TEIはそれを`undetermined`と読む。`accepted`と読む実装は、退役後の結果を成功として扱ってしまう。

## 一般化できない範囲

- D3は試験注入であり、製品の独立検証ではない。
- 実行したのは`validate`だけ。ビルド・コード生成・テストは未実行。
- ホスト1台、通信はloopback。
- 回復（新しいAttemptの作成）は観測していない。EKI #745の範囲。
- Windowsでは実行していない（固定コマンドがPOSIXラッパー、#312）。
