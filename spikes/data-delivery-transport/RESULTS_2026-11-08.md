# 2026-11-08 試験用UnixドメインソケットでのFixture送受信

## 対象と目的

Issue [#753](https://github.com/hat47x/eki-fabric/issues/753)の最初の物理的な通信検証。OSのUnixドメインソケットを使い、固定Fixtureに含まれる6つのイベントが、**実際のソケットを介して**欠落・重複・順序変更・内容の変化なく届くことを確認した。

この検証対象は[`unix_fixture_test.go`](unix_fixture_test.go)の**試験用送受信コード**であり、EKI本番のLocal IPC Adapter、既存の`WorkerPlaneService`、Lease/Grantの実認可、Connectデータ通信ではない。

## 実施環境と入力

| 項目 | 実際の内容 |

| 実施日 | 2026-11-08 |

| 実測パフォーマンス | 未取得。テスト実行時間から配送遅延p50/p95/p99を推測しない |

## 実行記録

作業用隔離ディレクトリで次を実行した。

~~~sh
gofmt -w unix_fixture_test.go
GO111MODULE=off go test -count=1 -v
GO111MODULE=off go test -race -count=5 ./...
~~~

**観測結果**：OSのソケットを介した6件の送受信テストがPASS。内容・順序照合の負例（欠落、重複、順序変更、内容改変）4件も期待どおり拒否。race付きで5回の繰返しがPASS。

## 一般化できる範囲／できない範囲

**確認できたこと**：このOS上のUnixドメインソケットは、6つのJSONイベントを同一プロセス内の二つのgoroutine間で配送できた。受信したイベントの全件・順序・内容が送信したFixtureと一致した。また同一の照合器で4つの改変が検出された。

**確認していないこと**：別プロセス通信、EKIの本番Worker・Adapterへの組込み、Control PlaneとData Planeの分離、実Lease/FenceEpochによる認可・失効・Result Acceptance、利用側のConsumed／TEI Provider Commit、Connectでの同等性、ネットワーク障害、バックプレッシャー、性能数値。これらは`NOT RUN`。

`lease_revoked`や`result_claim`という**イベントの文字列を送受信しただけ**で、実Leaseが失効したり、実Resultが拒否されたわけではない。`TestUnixSocketFixtureWireDelivery`をEKIの実データAdapterのPASSと解釈しない。
