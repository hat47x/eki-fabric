# Linux cgroup enforcement harness — 2026-09-18 初期観測

## この記録の位置付け

この文書は、`enforce/linux-cgroup` Harnessを作成した時点で実際に確認できた範囲を記録します。

delegation済みLinux hostでの最終的なResource Enforcement結果ではありません。

「確認できたこと」と「まだ確認できていないこと」を分け、実験していない保証を実証済みとして扱わないための記録です。

## 実行環境

確認にはLinux / amd64、Go 1.23.2の隔離された実行環境を使用しました。

この環境ではcgroup v2自体は利用されていましたが、現在のProcessへcgroup管理権限は委譲されていません。

## Unit Test

次を実行しました。

```bash
go test ./...
```

結果:

```text
ok  eki.local/cgroup-enforcement-spike
```

Unit Testでは少なくとも次を確認しています。

- `cpu.stat` の `usage_usec` を正しく読み取れる
- fixture上で `cpu.max`、`memory.max`、`pids.max` へ要求値を書き込める
- 存在しないtarget cgroupを安全側に拒否する

## 実cgroupに対するnegative path

現在の `/sys/fs/cgroup` をtargetとして、CPU quotaを書き込もうとしました。

```bash
go run . \
  -target /sys/fs/cgroup \
  -cpu-max "20000 100000"
```

環境からは、少なくとも次の既存値を読み取れました。

```text
cpu.max     = 400000 100000
memory.max  = 4294967296
pids.max    = max
```

一方、`cpu.max`、`memory.max`、`pids.max`、`io.max`、`cgroup.procs`、`cgroup.kill` は、このProcessから書込み不可でした。

HarnessはCPU quotaの適用要求に対し、次の理由で終了しました。

```text
cpu.max was requested but could not be applied
```

## この結果から確認できたこと

### 1. Capabilityの過大申告を避けられる

cgroup v2とCPU controllerが存在していても、書込みAuthorityがなければHarnessはCPU hard enforcementを成立扱いしません。

これはLocal Governorの共通契約で必要としている、

```text
feature exists
        !=
this worker can enforce it
```

という区別と一致します。

### 2. 現在の環境を使ったhard enforcement実測はできない

今回の環境ではdelegationがないため、CPU quotaの実効性、`memory.max`、`pids.max`、`io.max`、`cgroup.kill` の実測値は得ていません。

これらを実証済みとして扱いません。

## 次に必要な環境

次の測定には、専用のテスト用leaf cgroupへ必要なAuthorityを委譲したLinux hostが必要です。

systemdを使用する場合、`Delegate=` はUnit配下のResource Control subtreeをProcessへ委譲するための候補です。

ただし、正式なDeployment Architectureとしてsystemdを必須化したわけではありません。

次回測定では、少なくとも次を取得します。

| 測定 | 確認したいこと |
| --- | --- |
| CPU quota | `cpu.max` とobserved CPU shareの関係 |
| Memory limit | `memory.max` とOOM / `memory.events` |
| PID limit | `pids.max` と `pids.events` |
| Local stop | `cgroup.kill` からquiescenceまでの時間 |
| Cleanup | Agent終了後のProcess leak |
| I/O | `io.max` のDevice別実効性 |

## 参考

Linux kernelのcgroup v2仕様では、`pids.max` はTask数のhard limit、`memory.max` はMemoryのhard limitとして定義されています。また `cgroup.kill` は対象cgroupと子孫のProcessをkillするためのInterfaceです。

systemdの `Delegate=` は、Service / Scope内のProcessへ、そのUnit配下のResource Control partitioningを委譲するための設定です。
