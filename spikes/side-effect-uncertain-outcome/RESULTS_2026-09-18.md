## 確認した境界

- pure computeの通信断はretryable
- non-idempotent Taskでも副作用dispatch前ならretryable
- non-idempotent副作用をdispatch後、確認前に通信断するとUNKNOWN
- idempotent Taskは同じOperationID / RequestDigestでのみretry可能
- retry時に新しいOperationIDを発行して重複effectを隠せない
- 同じOperationIDを異なるIntentへ再利用できない
- idempotent external serviceは同じoperationを一度しか適用しない
- Workerが偽造したReceiptではcompleteへできない
- pinned external Effect AuthorityのReceiptをTask Intentへbindingできる
- cancelしてもdispatch済みnon-idempotent effectのUNKNOWNは消えない
- idempotencyが成立してもmax attemptsは別に適用される

## 重要な解釈

今回のSpikeで確認したのは、

> Workerの生死と、外部世界で副作用が成立したかどうかを別の状態として扱える

という点です。

Workerが消えたから副作用が失敗したとも、Workerが成功と申告したから成立したとも扱いません。

## Architectureへ残るもの

- Effect / Confirmation contractを外部Task APIへどこまで露出するか
- Application Adapter側で固定する情報
- Reconciliation Provider interface
- UNKNOWNの永続化
- Control Plane restart後の復元
- compensation / manual recovery
- External Effect Authorityのassurance
- 実際の外部APIでのidempotency semantics
