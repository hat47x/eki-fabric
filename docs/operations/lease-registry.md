# 台帳（lease registry）の置き場所

まもなく失効する貸与（Lease）を**回収する係**は、どの貸与が生きているかを知る必要があります。EKI はその一覧を**状態ストアではなくファイル**に持っています（`lease_registry`）。この文書は、**そのファイルが何のためにあり、どこに置き、無いと何が起きるか**を説明します。

## なぜ別のファイルなのか

- 貸与の一覧は**毎分書き換わります**。状態ストアの取引に混ぜると、**回収の掃除が状態の更新と競合**します。
- 回収は**止まっても被害が小さい**処理です（ADR-0037）。状態の正しさに関わる書き込みと、**同じ場所に置かない**ほうが安全です。

## 置き場所

- 配備の**永続ディスク**に置きます。**一時ディスクに置くと、再起動で回収の記憶が消えます**。
- パスは `lease_registry` で指定します。**相対パスは避け**、絶対パスを書きます（作業ディレクトリに依存させない）。
- バックアップは**状態ストアと同じ扱い**にします。片方だけ戻すと、**貸与の一覧と状態が食い違います**。

## 設定しないとどうなるか

`lease_registry` が空のとき、EKI は**回収を止めます**。起動時に警告を出します。

```text
lease reclaim is disabled: no lease_registry is configured, so expired leases are only found by whoever looks
```

**止まるのは回収だけで、貸与の発行や実行は続きます。** つまり、**期限切れの貸与が残ったまま**になり、資源の解放が遅れます。開発中は問題ありませんが、**本番では設定してください**。

## 台帳へ書き込む主体

配置ループ（`dispatch`）が Lease を予約した直後に、同じ `lease_registry` のファイルへその Lease を書きます（#745）。書き込みに失敗したときは、その Lease を Worker へ渡さず、そのTaskの配置を失敗として扱います。台帳に載らない Lease は、誰にも回収されないためです。予約済みの Lease は状態ストアに残り、期限が来れば失効します。

**回収は台帳から消すだけでなく、Attempt を閉じます（#745）。** 期限が切れた貸与について、結果（ResultClaim）が届いていなければ、`claimreconcile` の判断に従って Attempt を `lease_expired` として閉じ、そのあと台帳から消します。閉じたあとの再投入は `recoveryadmission` が決めます。

- **猶予（`RecallGrace`、30秒）の内側**では閉じず、台帳にも残します。次の走査がもう一度見ます。
- **外部作用がありうる場合**は閉じずに調停へ残す判断がありますが、**Task のモデルにその印がまだありません**（#745 の未決）。いまは全ての期限切れ Attempt を再試行可能として閉じます。
- **閉じるのに失敗した**ときは台帳の項目を消しません。次の走査が同じ項目を拾い直します。**消してから失敗すると、その Attempt は誰にも閉じられません**。

## 未決

- 一覧の**形式の版**（いまは JSON。将来変えるときの読み替え）。
