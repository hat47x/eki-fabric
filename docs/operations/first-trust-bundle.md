# 最初の Trust Bundle の版を入れる

新しい配備では、**信頼の起点になる版がまだ 1 つもありません**。この文書は、**最初の版を入れる手順**です。

判断の背景は [ADR-0036](../../plan/adr/0036-trust-bundle-distribution-and-rotation.md) §9 にあります（**版は API で入れる**／**最初の版だけ承認を要さない**）。

## なぜ最初の版だけ特別か

**承認の主体（Operator 証明書）が、版より後にしか作れない**からです。Operator 証明書は「どの CA を信じるか」に依存し、**その CA を並べたのが版**です。そこで**最初の版だけは承認を省き**、**設定の鍵（`trust_bundle_keys`）で署名されていること**を根拠にします。

**2 版目以降は必ず承認が要ります。** 初回の緩和は漏れません。

## 前提

| 用意するもの | どこに置くか |
| --- | --- |
| Control Plane の**署名鍵**（Ed25519 の秘密鍵） | **配備の外**（署名する人の手元） |
| その**公開鍵** | `trust_bundle_keys`（設定） |
| Administrator の**クライアント証明書** | Operator CA が発行。**初回は不要**（下記の代替あり） |

**Administrator の証明書がまだ無い場合**: 受理の経路は **Administrator の役割**を要求します。初回だけは、**配備の所有者が一時的に Administrator の証明書を 1 枚作る**か、**同じ鍵で署名した版を `POST /v1/admin/trust-bundles` に送れる環境**を用意してください（**監査には「誰が入れたか」が残ります**）。

## 手順

1. **版 1 を作る**（配備の外で署名する）。含めるもの:
   - `version`: `1`
   - `not_after`: **90 日後**（ADR-0036 §10）
   - `issuers`: **信頼する CA 証明書の SHA-256 指紋**（`openssl x509 -fingerprint -sha256` の値。**`sha256:` の接頭辞は付けない**）
   - `key_id`: **署名鍵の名前**（自称。記録では `verified_key` と並べて読む）
2. **設定に公開鍵を入れる**（`trust_bundle_keys`）。**この鍵が無いと受理の経路は開きません**。
3. **版 1 を送る**:

   ```http
   POST /v1/admin/trust-bundles
   {"version": 1, "signed": "<署名済み文書の base64>"}
   ```

   成功は **201**。失敗は **409**（`ADMISSION_REFUSED`）／**503**（`AUDIT_UNAVAILABLE`）。
4. **入ったことを確かめる**:

   ```http
   GET /v1/operator/trust-bundles/versions
   ```

   **版 1** が並び、**`verified_key` が設定した鍵の指紋**になっていることを確かめます。**`key_id` は自称**なので、**それだけで判断しないでください**。
5. **Operator CA を設定する**。ここから**承認を集める経路**が使えます（2 版目以降）。

## 失敗したときの見え方

| 症状 | 意味 |
| --- | --- |
| **404**（`NOT_FOUND`）が返る | **受理の経路が開いていない**。`trust_bundle_keys` が空か、署名鍵として解釈できない値 |
| **403**（`ADMINISTRATOR_ROLE_REQUIRED`） | **証明書の役割が違う**。Administrator の証明書が要ります |
| **409**（`ADMISSION_REFUSED`） | **署名が通らない**か、**版の内容が不正**（`version` が 0、`not_after` が過去など） |
| **503**（`AUDIT_UNAVAILABLE`） | **監査が書けない**。版は受理されていません（ADR-0040 §5 の fail closed） |

## してはいけないこと

- **`version` を 0 や空で送らない**（400 `INVALID_VERSION_DOCUMENT`）。
- **`issuer` に `sha256:` を付けない**（**16 進のみ**）。
- **最初の版に、後で消す予定の CA を入れない。** 版は**前進のみ**で、**ロールバックしません**（ADR-0036 §10.3）。**入れ直すには次の番号で版を作ります**。

## 何を保証しないか

- **最初の版が正しいこと**は確かめません。**設定の鍵を持つ人（配備の所有者）が正しい**という前提です。
- **受理の記録の完全性**は保証しません（監査の保存先は配備、ADR-0040）。
