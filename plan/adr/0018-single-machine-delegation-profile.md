# ADR-0018 一台で完結する配備形態（DP-7）を加え、制御層と依頼者をOSのアカウントで分ける

- 状態: **採用**
- 日付: 2026-10-21
- 関連: Issue [#131](https://github.com/hat47x/eki-fabric/issues/131)、[ADR-0013](0013-product-core-and-faces.md)、[ADR-0014](0014-authorities-for-delegation-budget-capacity.md)、[ADR-0016](0016-delegation-class-as-registered-profile.md)、[Deployment Profiles](../../architecture/DEPLOYMENT_PROFILES.md)、RQ-016、RQ-029、RQ-058、RQ-063、SEC-004

## 1. 背景

ADR-0013とRQ-063で、委任の核を一台のコンピューターの中だけでも使えるようにすることを決めました。開発者の端末でAI Agentに範囲を限ってコードを実行させる使い方は、分散のためでなくてもEKIを導入する入口になります。

既存の配備形態には、一台の構成としてDP-0（開発・試験）しかありません。DP-0は本番の安全性を主張しない形です。一台での本番の利用を表す配備形態がありませんでした。

一台の構成を考えると、依頼者（AI Agentなど）が、制御層と同じOSのユーザーとして動きやすいという問題があります。同じOSのユーザーなら、依頼者は制御層の鍵やmetadata storeを直接読み書きでき、受理、予算、委任の等級を素通りできます。RQ-016（依頼者は自分の権限を広げられない）とSEC-004（改変されたendpointは権限を広げられない）が、一台では成り立たなくなります。

## 2. 決定

1. 配備形態にDP-7（Single Machine Delegation）を加える。一台のコンピューターの中だけで委任の核を使う本番の構成とし、DP-0と区別する。
2. DP-7では、制御層（eki-control、metadata store、artifact store、signing key）を専用のOSのアカウントで動かし、依頼者のOSのユーザーから鍵とstoreを読み書きできないようにする。実行（worker agentとexecutor）は、制御層とも依頼者とも別のOSのアカウント、または隔離の仕組みの中で動かす。
3. 同じ人間が依頼者と管理者を兼ねる場合も、管理者の操作には別のcredentialを使う。AI Agentに、Admin credentialとOSの管理者権限を渡さない構成を推奨する。
4. 依頼者がOSの管理者権限を持つ場合に、依頼者がEKIそのものを書き換える攻撃は、DP-7の保証の範囲外とする。DP-7が保証するのは、依頼者が「EKIの操作として」権限を広げられないことまでである。
5. 外部の委任先（外部のLLM APIなど）は、管理者が委任の等級を登録した場合だけ使う。機密のData Classに届かない等級として登録することを標準にする。
6. Deployment ProfilesをBaseline 0.2へ上げる。

## 3. 移行

- M0とMVPの優先順位は変えない。DP-7は、ADR-0013の段階のS1（一台で完結する配備形態）で実装する。
- 現在の`eki-control`の参照実装は、DP-0として扱う。DP-7の条件（OSのアカウントの分離、端末内のcredentialの発行、鍵の保管）は、S1で加える。
- DP-7から、業務端末、専用のserver、クラウドへ委任先を広げるときに、依頼者との契約を変えない（RQ-063）。

## 4. 影響

### 良い点

- 分散を前提にせずにEKIを導入できる配備形態が、本番の安全性を保ったまま定義される。
- 一台の構成で起きやすい「依頼者が制御層を直接触れる」問題を、配備の条件として明示できる。

### 悪い点と制約

- 一台の構成でも、専用のOSのアカウントを二つ用意する手間が増える。インストーラや雛形で負担を下げる必要がある。
- OSによって、アカウントの分離や鍵の保管庫の仕組みが異なる。Windows、macOS、Linuxごとの実現方法は、実装のときに確かめる必要がある。

## 5. 未決事項

- Windows、macOS、Linuxで、制御層と実行のアカウントを分ける具体的な方法と、鍵の保管庫（DPAPI、Keychain、libsecretなど）の使い方。
- 隔離の仕組み（#132）を、DP-7の標準としてどれにするか。
- 一台の構成での、Local Governorの判断の入力（利用者の操作、端末上のほかのAI処理。#118）。
