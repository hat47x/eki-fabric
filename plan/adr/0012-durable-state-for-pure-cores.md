# ADR-0012 — 純粋な Core の永続化境界（暫定）

- Status: **Provisional（暫定）**
- Date: 2026-10-08
- 有効期間: 上位要件（業務フローとユースケース）が確定するまで。確定後に再判断する。
- Scope: Compute Grant の失効台帳（`internal/core/grant`）と、Federation の Registry（`internal/core/federation`）の永続化。
- 関連: ADR-0003（State Store）、ADR-0007（耐久性の前提）、ADR-0011（External Effect Adapter の境界）

## 1. 背景

Compute Grant の Ledger と Federation の Registry は、メモリ上の状態だけを持つ。プロセスが再起動すると、次が失われる。

- Grant の失効記録。失効した Grant が、再び受理される。
- Federation の失効済み Domain。Domain を再び Federation できてしまう。
- Bundle の最大版番号。巻き戻しの検出が効かなくなる。

これは安全性の問題である。ADR-0007 §4 が求める耐久性と同じ要求を、これらの Core にも満たす必要がある。

## 2. 制約

- Core パッケージは I/O、時計の読み取り、Goroutine を持たない。この性質は、各パッケージのテストで強制している。
- そのため、永続化の処理を Core の中に入れない。

## 3. 決定（暫定）

1. **Core は状態の値と、検証済みの遷移だけを提供する。** Core は、保存された状態から復元する API（Restore）と、状態を取り出す API（Snapshot）を持つ。どちらも I/O は持たない。
2. **永続化は Adapter 層のラッパーが担う。** 置き場所は `internal/adapters/reference/<name>/sqlite` とする。
3. **更新は次の順序で行う。**
   (a) ラッパーが内部の Core に遷移を適用する。検証は Core が行う。
   (b) 変化を一つのトランザクションで保存する。一意制約と単調性の検査は、DB 側でも行う。例えば、Grant の失効は Digest ごとに一つだけ、Bundle の版は増加のみ。
   (c) 保存が成功したあとにだけ、呼び出し元へ成功を返す。
   (d) 保存に失敗したら、内部の状態を保存済みの行から作り直す。
4. **保存された状態は信頼しない。** 復元のときに、Core が検査を行う。例えば、Federation は Bundle の署名を、復元時に固定された認可鍵で再検証する。改ざんや不整合は、復元の段階で拒否する。
5. **同時更新は DB のトランザクションで直列化する。** SQLite では BEGIN IMMEDIATE を使う。複数プロセスで Core の状態を共有しない。現時点の参照実装は、単一の書き手を前提とする。
6. **耐久性の契約を共通化する。** 次を conformance として定義する。close と reopen の後も状態が残ること、同じ失効を二重に記録すると一方だけが成功すること、保存に失敗したら状態が変わらないこと。

## 4. 代替案

- A. Core に Store のインターフェースを持たせ、Core が保存を呼ぶ。Core の純粋性に反するため採らない。
- B. Core のパッケージを I/O を持つものに変える。同じ理由で採らない。
- C. 永続化をせず、起動時に全件を外部から取り込む。取り込みの完全性を保証できないため採らない。

## 5. 結果

- 利点: Core の純粋性とテストを保てる。保存の失敗が状態の不整合を生まない（保存したあとにだけ確定する）。
- 欠点: 状態全体の Snapshot を扱うため、件数が多いと保存のコストが増える。Registry の件数が大きくなったら再判断する。
- 欠点: 複数プロセスでの共有は DB に依存する。現時点では単一の書き手を前提とする。

## 6. 見直しの条件

- 件数が増え、状態全体の Snapshot が現実的でなくなった。
- Control Plane の State Store（ADR-0003）と統合する必要が出た。
- Attempt / Lease の永続化（LSE-1）が入り、同じ DB に置くかどうかを判断する必要が出た。

## 7. 未決事項

- Registry の Snapshot の形式（版番号を付けた符号化）。
- 失効台帳と Registry を同じ DB に置くか、別の DB に置くか。
- 件数の上限と、その超過時の扱い。
